# Agent Note：标准 ACP 会话模型选择

Status: implemented

[English](2026-08-19-acp-session-model-selection.md) | 中文

## 问题

仅面向自动化的 ACP 桥接层过去使用一个部署级提供方／模型组合创建所有 Agent，且不返回会话配置。因此，ACP 宿主虽然能运行 DeepSeek Harness，却无法展示由适配器拥有的模型目录，也无法让单个会话使用用户选择的模型。若每个宿主都自行重做选择器，就必须猜测 Harness 能力，并会把配置所有权拆散在协议边界两侧。

桥接层必须继续作为自动化传输，不能重新膨胀成交互式产品界面。模型选择也不能修改部署级状态、耦合并发会话、把建议性目录当作全局请求校验，或让提示词身份与请求路由观察到不同模型。

## 决策

`@deepseek-ai/dsh-acp` 接受显式部署选项 `modelSelection: true`。插件启动时只读取一个已配置提供方由适配器拥有的 `listModels()` 目录。只有同时提供 `provider` 与 `model`、目录非空且已配置默认模型属于该目录时才能启动，否则明确失败。未启用的部署保留固定路由行为，也不公开 `session/set_config_option`。

启用后，`session/new` 返回一个 id 与 category 都为 `model` 的标准 ACP 单选项。选项值保留适配器顺序、ID、名称和描述；桥接层不增加宿主专用元数据，也不维护第二份目录。每个新会话拥有独立的 `ModelSelectionRef`，并通过 `installModelSelection()` 安装到该 Agent 的作用域。现有原语会为提示词组装和请求路由一同快照提供方、模型和可选推理强度，因此 `{{model}}` 与实际请求始终一致。

`session/set_config_option` 只接受 `model` 配置项，以及启动目录中的确切值。未知配置项 ID、布尔值、未知模型、未知会话，以及提示词执行期间的变更都会被拒绝且不修改状态。成功变更只更新指定会话，并返回完整的当前配置项集合。选择只有在现有请求头记录模型调用时才成为持久事实；系统不新增并行的选择事件或持久化真源。

部署可以提供 `modelReasoningDefaults`，即来自同一目录权威的显式模型 ID 到原生推理强度的映射。启动时在接受会话前，逐项按确切适配器路由校验。新会话和空闲模型切换会原子替换完整选择；下一个模型没有已配置覆盖值时，也会移除原有强度。提供方级强度无法表达异构模型默认值：它可能把不受支持的档位带入另一会话，或悄悄改变原生推理行为。桥接层使用现有选择原语，不转换提供方请求体，也不公开强度选择器。

ACP 图片能力属于连接级，而模型选择属于会话级。因此，启用选择的桥接层只有在附件存储存在，且每条可选路由都解析为明确支持图片输入时才公布图片能力。每次提示词准入仍会检查所选的确切路由。

`@deepseek-ai/dsh-acp-demo` 透传该显式选项。ACP 快照 harness 新增一个 `setModel` 动作，并通过可运行应用中的一条组装式、无密钥场景固定目录发现和标准协议更新。

## 考虑过的替代方案

**在每个 ACP 宿主中构建选择器。** 拒绝，因为宿主将不得不自行发明模型名称、可用性和校验规则，而不是渲染 Agent 的标准协议约定。

**在第一次改动中公开全部可配置提供方和模型。** 拒绝，因为部署已经拥有一个提供方路由。跨提供方选择器会引入分组、凭据和路由策略问题，与恢复缺失的模型控制无关。

**增加通用配置贡献者注册表。** 拒绝，因为一个标准模型配置项不需要新框架。ACP Agent 接口本身就是扩展点；未来配置项应分别证明其必要性。

**修改 `AgentOptions` 或全局 LLM runtime。** 拒绝，因为这些对象属于创建级或部署级，会耦合会话。现有 Agent 作用域选择原语已经负责提示词／请求一致性。

**在活动提示词期间允许变更。** 拒绝，因为配置操作应具有一个清晰的轮次边界。调用方可以在当前提示词结算后更换模型。

## 结果

- ACP 宿主只需渲染一个官方、类型化配置项，不包含 DeepSeek Harness 模型选择特例。
- 适配器目录决定选择器展示什么；在这个显式目录驱动操作之外，目录成员关系仍然只是建议。
- 会话彼此隔离；模型选择不会在 Agent 或连接之间泄漏。
- 未启用的部署继续保持小型固定路由 ACP 界面。
- 推理强度选择器、模式、命令、会话导航和其他交互功能仍位于此自动化传输之外。

## 测试

协议测试覆盖目录投影、提示词／请求路由、非法值、启动失败和多会话隔离。无密钥组装快照通过真实 Loader 启动 `dsh-acp-demo`，并固定 `session/new`、`session/set_config_option`，以及已配置强度 → 适配器默认值 → 已配置强度的模型轮次和持久请求头。现有 ACP 生命周期、内容、权限和取消测试保持不变。
